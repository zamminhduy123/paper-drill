Scope → dataset mapping (fixed vocabulary)

* ivn: Car-Hacking, ROAD, CIC-IoV-2024, CAN-ML
* iot-ids: N-BaIoT, TON_IoT, CIC-IoT-2023
* nids: CIC-IDS-2017, UNSW-NB15, CIC-DDoS-2019

Framing: three transfer levels

Raw feature spaces differ (8-byte CAN frames vs. IoT flow stats vs. enterprise flows), so "method transfer" should be explicit about what transfers:

* L1 – Protocol transfer: evaluation methodology (zero-day leave-one-family-out, temporal splits).
* L2 – Feature-family transfer: scope-invariant primitives (inter-arrival time, rates, counts, ID/port entropy).
* L3 – Algorithm transfer: model recipes (per-unit hierarchies, self-training, cost-sensitive ensembles).

Proposed transfer ideas

NIDS → ivn

1. LOFO zero-day protocol (UNSW-NB15, CIC-IDS-2017) -> unseen-attack evaluation on ROAD, CAN-ML, CIC-IoV-2024 (L1). Hold out each attack family in turn; compare supervised vs. one-class vs. hybrid backbones.
2. Rare-class imbalance handling (CIC-DDoS-2019 reflection families) -> rare IVN families (fuzzy, combined spoofing) (L3).
3. Flow-window statistics (CIC-IDS-2017, UNSW-NB15) -> CAN ID-session aggregation on Car-Hacking, ROAD (L2). Treat CAN ID as the flow tuple; test whether flow-style stats beat raw-frame features.

ivn → iot-ids 4. IDT/periodicity baselining (Car-Hacking, ROAD) -> periodic-telemetry anomaly detection on TON_IoT, N-BaIoT (L2/L3). Compromised devices perturb benign periodicity; baseline + drift detection. 5. Cross-signal plausibility checks for spoofing (CIC-IoV-2024) -> cross-metric consistency on TON_IoT telemetry (L3). Semantics transfer: "physically impossible pairs" → "statistically inconsistent metric pairs." 6. Per-ID allowlisting + rate monitoring -> per-port/per-host rate baselining on CIC-IoT-2023 Recon/scanning families (L2).

iot-ids → ivn 7. Per-device fingerprinted models with global+residual hierarchy (N-BaIoT) -> per-ECU/per-CAN-ID hierarchy on ROAD, Car-Hacking (L3). Structural analogy: device ↔ EU/ID. Clean ablation: global-only vs. per-unit-only vs. hybrid. 8. Semi-supervised self-training under label scarcity (TON_IoT) -> label-scarce CAN detection on benign-dominant ROAD drives (L3). 9. Mirai-family scanning/burst detection (CIC-IoT-2023) -> bus-wide fuzzing/scanning detection on CAN-ML, ROAD (L2).

iot-ids ↔ nids 10. Hierarchical family taxonomy (CIC-IoT-2023's 7 categories) -> rare-class hierarchical classification on UNSW-NB15 (9 categories), CIC-IDS-2017 (L3). Target: Worms, Shellcode, Heartbleed-tier rare classes. 11. Volumetric early-warning (CIC-DDoS-2019) -> few-shot early DDoS/scanning detection on CIC-IoT-2023 (L3). Metric: detection at first-k packets.

ivn → nids (stretch) 12. Strict whitelisting + fixed-period verification -> beacon-style C2 detection on CIC-IDS-2017 Botnet/Infiltration (L2).

Concrete research splits

* Split A (sanity gate): Train Car-Hacking + ROAD → zero-shot test on CIC-IoV-2024 and CAN-ML. Establishes within-scope transferability before any cross-scope claim.
* Split B (unifying LOFO grid): Leave-one-family-out across all ten datasets (ROAD spoofing/fuzzing scenarios; CAN-ML families; CIC-IoT-2023's 7 categories; UNSW-NB15's 9 categories; CIC-IDS-2017 groups; CIC-DDoS-2019 volumetric vs. reflection). One identical backbone → apples-to-apples zero-day comparison across all three scopes.
* Split C (per-unit hierarchy): Stage 1: N-BaIoT per-device models → global+residual hierarchy. Stage 2: identical recipe per-CAN-ID, train ROAD → validate Car-Hacking → test CIC-IoV-2024.
* Split D (timing-only cross-scope): Recompute a uniform timing/rate/entropy feature family everywhere (CAN inter-arrival times; IoT/NIDS inter-packet times and rates). Fit benign-only baselines on ROAD + TON_IoT benign; evaluate on CIC-IoV-2024 spoofing and CIC-IoT-2023 scanning/Mirai families. The cleanest true cross-scope transfer.
* Split E (volumetric few-shot chain): Train CIC-DDoS-2019 → few-shot adapt (k labeled samples/class) to CIC-IoT-2023 → then to Car-Hacking/CAN-ML DoS via rate features.
* Split F (label-scarce chain): TON_IoT small-labeled/unlabeled self-training recipe → ROAD and CIC-IoV-2024 spoofing at ≤1% labeled budget.
* Split G (consistency transfer): Fit cross-signal consistency on CIC-IoV-2024 spoofing families → port the method to TON_IoT cross-metric telemetry consistency.

Priority for the thesis: A → B → D as the core (protocol transfer + timing transfer are the most defensible); C and E as the strongest "named-method" chapters.

Optional fill-ins for the blank limitation sections

* iot-ids: "No explicit limitations stated in the provided text. Datasets are public and not redistributed; source DOIs cited; preprocessing/cache pipeline provided in the README."
* nids: Same pattern, plus (if you want content): "Flow statistics are precomputed, which limits raw-packet-level methods; strong class imbalance in rare attack families (e.g., Heartbleed, Worms) constrains supervised evaluation."

One methodological rule to state up front: never train and test on the same dataset when claiming transfer — hold out either by dataset (Split A/C/E) or by attack family (Split B/F), and report L2 and L3 results separately so the thesis can attribute gains to features vs. algorithms.
