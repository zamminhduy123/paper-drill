Since your "Explicit limitations" section is blank, I've proposed a limitations list you can adapt, followed by concrete research splits built only on Car-Hacking, ROAD, CIC-IoV-2024, and CAN-ML.

Explicit limitations (proposed)

* Scope: deep-learning-based intrusion detection at the network level of classic-CAN in-vehicle networks; no host/ECU firmware analysis, no gateway or AUTOSAR-layer security, no CAN-FD or Automotive Ethernet (all four datasets are classic CAN).
* Attack model: injection-style adversaries as captured in the four public datasets (DoS, fuzzing, spoofing, etc.); no red-teaming on real vehicles.
* Evaluation: offline, PC-based; no in-vehicle hardware testbed. Runtime is reported via proxies (CPU inference latency, params, memory).
* Task boundary: detection/alerting only — no mitigation, response, recovery, or attacker attribution.
* Data: only the four public datasets; results may not transfer to proprietary fleets; each dataset has its own label taxonomy, so cross-dataset label mapping is approximate and stated as such.
* Modeling: deep learning is the object of study; non-DL models (e.g., tree ensembles) are admitted only as baselines for context.

Research splits

Split 1 — In-distribution supervised benchmark

* RQ1: How well do standard deep architectures classify CAN intrusions when train/test share a distribution?
* Data: Car-Hacking, CAN-ML, CIC-IoV-2024 (ROAD reserved for Splits 3–4 to avoid tuning leakage).
* Protocol: two variants per dataset — (a) stratified random 70/15/15; (b) chronological 70/15/15 within each capture (early frames train, late frames test). Report both; the gap is itself a result.
* Inputs (ablation): raw frame (ID + DLC + 8 payload bytes, byte embeddings); ID one-hot only; payload-only with ID masked; delta-t sequences.
* Models: MLP, 1D-CNN, BiLSTM, Transformer encoder (sequence lengths 20–100 frames).
* Metrics: macro-F1, per-class recall, balanced accuracy; 3 seeds, mean ± std.

Split 2 — Cross-dataset generalization (transfer matrix)

* RQ2: Do detectors transfer across capture setups without retraining?
* For every ordered pair (train A → test B) among the four datasets where label axes overlap: DoS↔DoS, fuzzing↔fuzzy, spoofing-family↔spoofing-family (approximate mapping, documented). ROAD attacks are always test-only.
* Settings: (i) zero-shot; (ii) threshold calibration using 1,000 benign target frames only.
* Metrics: per-family AUROC; recall at FPR = 10⁻³; false alarms per hour on target benign.
* Deliverable: 4×4 transfer matrix + failure-family analysis.

Split 3 — Realistic anomaly detection on ROAD

* RQ3: Can benign-only deep models detect realistic contextual spoofing?
* Train on ROAD benign traffic (multiple operating contexts): LSTM/GRU autoencoder, transformer autoencoder.
* Test on ROAD's held-out attacks (never in training), plus an open-set probe: unseen families from CIC-IoV-2024 raw frames (e.g., fuzzing, DoS) mapped into the same frame schema.
* Sweeps: window size 20/50/100/200 frames; context-shift ablation (train on one operating context, test on another).
* Metrics: per-attack recall, FPR/h on benign contexts, detection latency in frames.

Split 4 — Robustness audit (shortcuts, imbalance, noise)

* RQ4: How much of reported accuracy is artifact?
* Experiments on Car-Hacking (primary), CAN-ML, CIC-IoV-2024 raw: drop ID / constant-ID / shuffled-ID runs; deduplicate injection bursts; down-sample attacks to 1:100 and 1:1000 vs. benign; inject 1–5% label noise on CAN-ML features.
* Deliverable: corrected benchmark numbers + a reusable audit checklist; show where model rankings change.

Split 5 — Deployment-proxy efficiency study

* RQ5: What is the accuracy–cost Pareto frontier for in-ECU inference?
* Take the best two models from Splits 1–3; prune/distill; measure params, peak memory, CPU ms/frame, throughput.
* Final confirmation on Car-Hacking (fast iteration) and CIC-IoV-2024 raw (broad taxonomy).
* Deliverable: Pareto plot and a recommended operating point (e.g., ≥0.95 recall @ ≤1 false alarm/hour within a stated latency budget).

Reporting standard (applies to all splits)

* Session-wise/capture-wise splits wherever multiple captures exist; never random-shuffle overlapping sequence windows across train/test.
* FPR/h computed from actual benign frame counts per hour, not ratios.
* Everything seeded; report mean ± std over ≥3 seeds.
* State the label-mapping assumptions explicitly in Split 2.

Thesis narrative

S1 (baselines) → S4 (audit: what's real) → S3 (realistic detection) → S2 (generalization) → S5 (efficiency). If time-constrained, S1 + S4 + S3 alone form a defensible thesis: benchmark, honest audit, and realistic detection.
